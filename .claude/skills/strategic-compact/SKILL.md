# Strategic Compact — 단계 경계에서 압축하기

자동 압축은 작업 한가운데서 일어나 파일 경로·부분 상태를 잃게 만든다. 단계가 끝나는 지점에서 직접 압축한다.

## 언제 압축하나

| 단계 전환 | 압축? | 이유 |
|---|---|---|
| 조사 → 계획 | 예 | 조사 내용은 크고, 남길 것은 계획뿐 |
| 계획 → 구현 | 예 | 계획을 **파일에 적은 뒤** |
| 구현 → 검증 | 경우에 따라 | 방금 고친 코드를 계속 볼 거면 유지 |
| 디버깅 끝 → 다음 기능 | 예 | 스택트레이스가 다음 작업을 흐린다 |
| 구현 도중 | 아니오 | 변수명·경로·부분 상태 손실이 크다 |
| 실패한 접근 뒤 | 예 | 막다른 추론을 비우고 다시 |

## 압축 전에 반드시 적는다 (이 저장소 규칙)

태스크 목록 도구는 환경에 따라 없을 수 있으니 믿지 않는다. 남는 것은 **파일과 git**뿐이다.

1. 여러 단계 작업이면 `DESIGN_PROMPTS/planning/WORK_QUEUE.md`의 해당 항목 "메모"에 **마지막으로 한 일 / 다음 할 일**.
2. 검증 전 중간 상태면 작업 브랜치에 `wip:` 커밋 + push(master 금지).
3. 그다음 `/compact 다음은 <항목>의 <단계>` 처럼 요약을 붙여 압축.

압축 뒤 다시 시작할 때는 `PROMPT_resume.md` 절차(큐 → `git log --oneline -10`·`git status` 대조 → 🔄 항목부터).

## 압축해도 남는 것 / 사라지는 것

| 남음 | 사라짐 |
|---|---|
| CLAUDE.md, PROJECT_MEMORY.md | 중간 추론 |
| 디스크의 파일, 커밋 | 앞서 읽은 파일 내용 |
| WORK_QUEUE.md 메모 | 말로만 들은 사용자 선호(→ 메모리·문서에 적을 것) |

## 컨텍스트를 아끼는 습관

- CLAUDE.md는 항상 로드된다 — 먼저 PROJECT_MEMORY.md를 보고, CLAUDE.md는 필요한 절만 `grep -n`으로 찾아 읽는다.
- 큰 파일은 `sed -n 'a,bp'`로 필요한 부분만, 테스트 로그는 `tail`로.
- 같은 규칙을 CLAUDE.md와 스킬에 중복해서 적지 않는다(이번에 CLAUDE.md의 1,234줄 중복을 지운 이유).
