1. 프로젝트 개요·목표

사진을 좋아하는 사람들이 매월 출사 날짜를 함께 정하고, AI가 계절에 맞는 장소·제철 음식을 제안하고, 출사 당일 사진과 스토리를 공유해 앨범으로 남긴다.

회원가입→월간 출사 투표→날짜 확정(모임 생성)→AI 계절 추천→참가 신청→출사 시작→사진 공유→스토리 제작→인스타그램 공유→앨범·베스트 포토

핵심 원칙

  • 모든 버튼은 실제 API에 연결, 모든 입력은 DB에 저장, 회원별 데이터 분리.
  • 투표는 서버에서 실제 집계 — 모든 회원에게 같은 결과.
  • 외부 API 키가 없으면 "연결 준비" 상태와 개발용 샘플을 표시로 구분. 확인되지 않은 주소·영업시간·날씨·개화 상태를 사실처럼 보여 주지 않는다.

3. 사용자 흐름

  1. 운영자가 2027년 3월 투표를 만든다 → 그 달 토·일·공휴일이 후보로 자동 추가, 필요하면 평일 추가.
  2. 회원은 달력에서 날짜마다 "가능/불가"를 고른다(여러 날짜, 언제든 수정). 응답 안 한 날짜는 미응답.
  3. 날짜마다 가능 인원이 집계되고 최다 날짜가 "추천"으로 표시된다(최소 인원 미달이면 추천 안 함).
  4. 마감 후 운영자가 날짜·시간·집합 장소를 정해 확정 → 모임이 생성되고 가능 응답자에게 알림.
  5. 모임 상세에서 AI 추천을 받아 장소를 비교하고 장소 투표 후보로 등록.
  6. 회원은 참가 신청(투표의 "가능"과 별도 단계, 정원 초과 시 대기자).
  7. 당일 운영자가 출사 시작 → 피드에 사진·글, 좋아요·댓글.
  8. 참여자는 스토리를 만들어 저장·공유하고 태그 문구를 복사.
  9. 운영자가 출사 종료 → 앨범 공개, 참여자가 베스트 포토 3표.

5. 디자인 시스템

Toss 디자인 시스템(DESIGN_PROMPT_toss-design-system.md) 그대로: 단일 브랜드 블루, 배경 #F2F4F6, 흰 카드, 블러·그라디언트 금지, 회색 그림자만, 이모지 아이콘, 공통 Button·FormField, 스켈레톤·빈 상태 필수, WCAG AA. 사진이 주인공 — 큰 썸네일·둥근 모서리(12~16px)·넉넉한 여백. 달력 색: 토요일 텍스트 primary, 일요일·공휴일 danger, 확정일 블루 채움, 내 "가능" 초록 톤(successText), "불가" 회색. 상세는 DESIGN_PROMPTS/design/DESIGN_PROMPT_snapday-outing.md.

6. 월간 출사 투표 규칙

  • 월 1개(같은 달 중복 생성 불가). 2027년 1~12월 모두 생성 가능(다른 해도 가능).
  • 후보: 그 달의 모든 토·일 + 등록된 공휴일(대체공휴일 포함). 평일은 운영자가 추가.
  • 응답: 날짜마다 가능 / 불가, 응답 없으면 미응답. 선호도가 아닌 실제 참여 가능 여부.
  • 투표 기간(시작~마감) 안, 상태 OPEN일 때만 저장·수정. 마감 시각이 지나면 배치가 CLOSED로.
  • 집계: 날짜별 가능·불가 인원, 응답자 수. 추천 = 가능 인원 최다 날짜(동률 모두), 최소 인원이 있으면 그 이상인 날짜만.
  • 자동 확정 없음 — 운영자가 확정. 확정 시 모임 생성(제목·장소·시간·정원), 이후 투표는 읽기 전용.
  • 알림: 생성(대상자), 마감 24시간 전(미응답 대상자, 1회), 확정(가능 응답자), 리마인드(운영자 버튼). 대상자 = 최근 6개월 출사 참여자 ∪ 지난 투표 응답자.
  • 공휴일은 코드에 박지 않는다: 공공데이터포털 특일정보 API(HOLIDAY_API_KEY)로 가져오거나 관리자가 등록.

7. AI 출사 추천 규칙

  • 입력: 출사 날짜·요일·계절, 지역(모임 장소·투표 지역), 참여자 촬영 취향 분포, 추가 질문.
  • 출력: 요약, 장소 2~4곳(지역·이유·추천 시간·촬영 포인트·콘셉트·우천 대안), 제철 음식, 맛집 찾기 팁, 교통·주차 일반 안내, 날씨·개화 관련 주의(예상임을 명시).
  • 만들지 않는 것: 주소·영업시간·전화번호·가격·확정 개화일·실제 날씨. 화면에 "AI 생성 정보 — 방문 전 확인" 고정 표시, 장소는 카카오맵 검색 링크.
  • 키 없음 → SAMPLE 배지의 개발용 일반 안내(실제 장소 아님). AI 결과와 섞지 않음.
  • 저장된 추천은 모임 단위로 누구나 열람, 다시 받기·추가 질문은 새 기록. 회원당 10분 5회.

8. 출사 관리·현장 모드

상태: RECRUITING(모집) → RECRUITMENT_CLOSED → SCHEDULED → ONGOING(현장 모드) → ENDED(앨범). 기존 시간 기반 배치 전환은 그대로, 만든 사람·관리자가 "출사 시작"·"출사 종료"로 앞당길 수 있다. 시작하면 피드 작성·좋아요·댓글이 열리고, 종료하면 피드가 닫히고 앨범·베스트 포토 투표가 열린다. 참가 신청(정원·대기자 자동 승격)은 기존 규칙.

9. 사진·앨범·베스트 포토

  • 사진 업로드: 기존 업로드 API(형식·20MB 검사, UUID 파일명, 진행률).
  • 앨범: 종료된 모임의 피드 사진 모음 — 최신/인기 정렬, 회원 필터, 스토리 모음.
  • 베스트 포토: 종료 후 참여자만, 1인 최대 3표(사진당 1표), 득표순 순위·대표 배지. 월간·연말 베스트는 다음 단계.

10. 스토리 제작·인스타그램 공유

  • 1080×1920(9:16) 캔버스. 사진 1~3장 레이아웃, 배경색, 텍스트(추가·크기·드래그), 스티커(날짜·위치·출사명).
  • 멤버 태그: 모임 참여자 중 인스타그램 ID 등록자를 불러와 선택 → @a @b 문구 생성·전체 복사.
  • 저장: PNG 내려받기, 스토리 등록(업로드 후 모임 스토리에 표시), 공유: 운영체제 공유 시트(지원 브라우저) — 인스타그램 앱 선택은 사용자가.
  • 인스타그램 멘션 자동 등록·음악 자동 삽입은 공식 API로 불가 → 태그 문구를 복사해 사용자가 스토리에서 적용한다(화면에 안내).

11. 관리자 기능

14. 보안 정책

  • 모든 쓰기는 토큰의 회원 기준(요청 본문의 회원 id를 믿지 않음), 관리자 기능은 서버에서 WM/SA 검사.
  • 투표·베스트 표 중복은 DB 유니크 + 서비스 검사. AI·공휴일 키는 서버 환경 변수만.
  • 인스타그램 ID는 같은 모임 참여자에게만 태그 후보로 노출(기존 규칙). 연락처는 응답에 넣지 않음.
  • 회원 탈퇴 시 투표·베스트 표·스토리·AI 기록 삭제. 신고·차단 기존 기능. 사진 저작권·초상권은 약관(모임 인물 동의 안내 기존).
  • Supabase 공개 키 직접 접근 차단: backend/db/supabase-lockdown.sql(RLS + 권한 회수, 운영 실행 필요).

15. 개발 로드맵
