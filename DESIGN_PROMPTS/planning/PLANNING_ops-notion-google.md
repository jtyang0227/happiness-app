# 해피니스 운영 자동화 통합 기획서 (노션 + 구글 + Gemini)

작성: 2026-11-27 · 기획자 에이전트(Jetty ③ 새 프로젝트) · 대상: jtyang0227/happiness-app (운영 API = NestJS `apps/api`, 전환 중인 Spring `backend/`는 손대지 않음)

## 1. 목표
운영자(작가·관리자) 한 명이 **노션 한 화면**에서 예약·문의·할 일·주간 현황을 보고, 반복 작업(일정 등록, 문의 분류, 답장 초안, 리포트)은 자동으로 준비되게 한다.

성공 기준(4주 후)
- 새 예약·문의가 1분 안에 노션 DB에 나타난다(수동 복사 0건).
- 촬영 전날 알림을 놓치는 일이 0건이다.
- 문의 메일 답장 초안이 자동으로 준비되고, 발송은 사람이 누른다.
- 매주 월요일 아침 주간 리포트(예약 수·매출·문의·할 일)가 노션에 쌓인다.

## 2. 구성도
```
[웹/앱 사용자] ──예약·문의──▶ [apps/api (NestJS)] ──DB(Postgres)
                                   │
                                   ├─(A) OpsNotionService ──▶ 노션 「예약」「문의」 DB   (실시간, 코드)
                                   └─(D) Gemini (기존 키)  ──▶ 사진 설명·태그, 후기 요약 (코드, 3단계)

[노션 「해피니스 운영 센터」] ◀── 대시보드: 예약 보드·캘린더 / 문의 수신함 / 할 일 / 작가 / 주간 리포트
        │
        └─(B) 노션 캘린더 ⇄ 구글 캘린더 (예약 DB의 촬영일·납품 기한을 그대로 표시, 코드 없음)

[Claude 정기 실행 (커넥터)]
   ├─(C) 매일 09:00 Gmail 「해피니스/문의」 분류 → 노션 문의 DB + Gmail 답장 초안(발송 X)
   ├─(B') 매일 18:00 내일 촬영 예약 → 구글 캘린더 「해피니스 촬영」 일정 + 30분 전 알림
   └─(E) 매주 월 09:00 주간 리포트 → 노션 「주간 리포트」 페이지 + 구글 시트 행 추가
```

## 3. 데이터 흐름과 키
| 흐름 | 출발 | 도착 | 중복 방지 키 | 실패 시 |
|---|---|---|---|---|
| A1 예약 생성 | `BookingService.create` | 노션 예약 DB 새 행 | `예약 ID`(DB id) | 로그 경고만, 예약은 성공 |
| A2 예약 상태 변경 | confirm/reject/cancel/payment/checklist | 같은 행 업데이트 | `예약 ID`로 조회 후 수정 | 같음 |
| A3 문의 생성 | `InquiryController.create` | 노션 문의 DB 새 행 | `문의 ID` | 같음 |
| B 일정 | 노션 예약 DB(촬영일) | 구글 캘린더 | 일정 설명에 `happiness-booking:{id}` | 다음 실행에서 재시도 |
| C 메일 | Gmail 라벨 `해피니스/문의` | 노션 문의 DB(출처=Gmail) + 초안 | `Gmail 스레드 ID` | 라벨 `해피니스/확인필요` |
| E 리포트 | 노션 예약·문의·할 일 DB | 노션 리포트 페이지·시트 | 주차(YYYY-Www) | 다음 주 재생성 |

개인정보 규칙: 노션에는 **고객 이름(성+이름 첫 글자 마스킹)·촬영 정보만** 기본 저장. 전화·이메일은 `OPS_NOTION_INCLUDE_CONTACT=true`일 때만(운영자 결정). 실제 고객 데이터를 노션으로 보내기 시작하는 시점(=토큰 등록)은 사용자가 정한다.

## 4. 우선순위
| 순위 | 항목 | 이유 | 방식 |
|---|---|---|---|
| P1 | 노션 운영 센터 + 예약·문의 실시간 동기화(A) | 모든 자동화의 바닥 데이터 | 노션 구성 + 코드 PR |
| P2 | 캘린더(B/B') | 촬영 누락 방지, 노션 캘린더는 코드 0 | 노션 캘린더 연결 + 정기 실행 |
| P2 | Gmail 문의 분류·초안(C) | 응답 속도 | 정기 실행 |
| P3 | 주간 리포트(E) | 데이터가 2주 이상 쌓여야 의미 | 정기 실행 |
| P4 | Gemini 사진 설명·태그·후기 요약(D) | 기존 `AutoTagService`(Vision)와 역할 정리 필요 | 코드 PR |

## 5. 단계별 범위
- **1단계(오늘)**: 노션 「해피니스 운영 센터」 페이지와 DB 5개(예약·문의·작가·할 일·주간 리포트), 대시보드 뷰. Gmail 라벨. `apps/api/src/ops/` 노션 동기화 PR(환경변수 없으면 아무것도 안 함).
- **2단계(토큰 등록 후)**: Railway/Render에 `NOTION_TOKEN` 등 등록 → 실제 예약으로 확인. 노션 캘린더 앱에서 구글 계정 연결 + 예약 DB 표시. Gmail·캘린더 정기 실행 켜기.
- **3단계**: 주간 리포트 정기 실행, 구글 시트 「해피니스 주간 지표」.
- **4단계**: Gemini 사진 설명·태그 추천(관리자 승인 후 반영), 후기 요약.

## 6. 위험과 대응
| 위험 | 대응 |
|---|---|
| 노션 API 장애·느림이 예약을 막음 | 비동기(fire-and-forget) + 3초 타임아웃, 예외 삼킴·경고 로그 |
| 고객 개인정보 외부 저장 | 기본 마스킹, 연락처는 옵션, 노션 페이지 비공개 유지(외부 공유 금지) |
| 메일 오발송 | 정기 실행은 **초안만** 만들고 발송 도구는 쓰지 않음 |
| 중복 행 | 예약 ID·문의 ID·스레드 ID로 upsert |
| Spring/Nest 전환 중 이중 실행 | 동기화는 Nest에만 넣음(Spring 미수정). 컷오버 전엔 Nest로 들어온 요청만 동기화됨 → 2단계에서 확인 |
| 다른 스레드(서버 시간 모듈) 충돌 | `apps/api/src/ops/` 새 폴더 + `app.module.ts` providers 한 줄만 추가 |
| 시크릿 노출 | 토큰은 환경변수만, 코드·문서·메모리에 값 기록 금지 |

## 7. 사용자가 할 일(최소)
1. 노션 통합(Internal Integration) 만들기 → 토큰을 배포 환경변수 `NOTION_TOKEN`에 직접 입력, 「해피니스 운영 센터」 페이지에 통합 연결.
2. PR 리뷰·병합.
3. 노션 캘린더에서 구글 계정 연결(선택).
4. 정기 실행 3개(C·B'·E) 켤지 결정.
