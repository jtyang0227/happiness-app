# Behance 공개 기능 분석 — Happiness 앱과의 격차 (2026-10-20)

> **분석 방법과 한계 (먼저 읽을 것)**
> - REA(Reverse Engineer Anything)로 분석하려 했으나, 이 클라우드 환경의 네트워크 정책이 `behance.net`·`www.behance.net`을
>   포함한 외부 사이트 접속을 모두 차단해 실행하지 못했다(같은 이유로 Cosmos·SCRL도 불가).
> - 따라서 이 문서는 **Behance에 대해 공개적으로 알려진 기능**(서비스 소개·도움말에서 널리 알려진 내용, 작성자의 사전 지식 기준)을
>   정리한 것이며, 실시간 화면·네트워크·코드 분석 결과가 아니다. 최근 UI 개편이나 지역별 차이는 반영되지 않았을 수 있다.
> - Behance의 코드·디자인·에셋은 참고하지 않으며, 기능의 **개념**만 Happiness의 제품 방향("보여주기 → 일 받기 → 일 처리하기",
>   `MASTER_PLAN_happiness-app.md`)과 Toss 디자인 시스템에 맞게 재해석한다.
> - 앱 쪽 현황은 이 저장소 코드를 직접 확인한 결과다(파일 경로 표기).

## 1. Behance는 무엇을 하는 서비스인가

Adobe가 운영하는 크리에이티브 포트폴리오 네트워크. 핵심 루프는 세 단계다.

1. **보여주기** — 작업을 "프로젝트" 단위(여러 이미지·글·영상을 묶은 케이스 스터디)로 올린다.
2. **발견되기** — 탐색(분야·도구·색상·지역 필터, 정렬), 큐레이션("Featured" 선정), 팔로우 피드, 추천으로 노출된다.
3. **일 받기** — 프로필의 "고용 가능" 상태, 서비스(가격이 붙은 작업 상품), 메시지, 채용 게시판으로 의뢰가 이어진다.

Happiness는 1·3단계는 이미 상당 부분 갖췄고(작업 노트, 문의·예약·납품), **2단계 "발견되기"와 작업 단위 반응**이 상대적으로 비어 있다.

## 2. 기능별 대조표

상태: ✅ 있음 · 🟡 부분적 · ❌ 없음

### 2.1 프로젝트(작업 단위)

| Behance 기능 | 설명 | Happiness 현황 | 상태 |
|---|---|---|---|
| 프로젝트 = 케이스 스터디 | 커버 + 이미지·텍스트·영상 모듈을 순서대로 쌓은 한 건의 작업 | 시리즈 + 작업 노트(`Series` 유형·클라이언트·시기·이야기, `WorkCasePage`) | ✅ |
| 커버 이미지 지정 | 목록 카드에 쓰일 대표 이미지·크롭 | `Series.coverImageUrl` | ✅ |
| 텍스트 모듈을 사진 사이에 배치 | 이미지와 글을 번갈아 배치 | 작업 이야기는 사진 위 한 덩어리, 사진별 캡션은 사진 제목만 | 🟡 |
| 영상·임베드 모듈 | 동영상/외부 임베드 | 포트폴리오 커버 영상(`coverVideoUrl`)만, 작업 안에는 없음 | ❌ |
| 분야(Creative Fields) 최대 3개 | 작업 분류 | 사진 단위 장르(주 1 + 서브 2), 작업은 촬영 유형 1개 | ✅ |
| 사용 도구(Tools Used) | 어떤 툴로 만들었는지 표기 | 사진별 EXIF(카메라·렌즈·조리개 등) | ✅ (사진 단위) |
| 공동 작업자 크레딧(Co-owners/Credits) | 여러 명이 한 프로젝트의 소유자·기여자로 표시 | 없음 (`grep credit/coOwner` 결과 없음) | ❌ |
| 초안·예약 발행 | 공개 전 저장, 예약 공개 | 시리즈는 생성 즉시 공개, 초안 개념 없음 | ❌ |
| 저작권·라이선스 표기 | 모든 권리 보유 / CC 라이선스 선택 | 없음 | ❌ |
| 성인 콘텐츠 표시 | 민감 콘텐츠 가림 | 없음(신고 기능은 있음) | ❌ |

### 2.2 반응과 지표

| Behance 기능 | 설명 | Happiness 현황 | 상태 |
|---|---|---|---|
| 감상(Appreciate) | 프로젝트 단위 좋아요, 공개 카운트 | **사진 단위**만(`PhotoLike`), 작업(시리즈) 단위 반응 없음 | 🟡 |
| 조회수 공개 | 카드·프로젝트에 조회수 표시 | 작가 본인 분석 대시보드에서만(PHOTO_VIEW/WORK_VIEW) | 🟡 |
| 댓글 | 프로젝트 댓글 | 사진 댓글·대댓글(`comment/`), 작업 단위 댓글 없음 | 🟡 |
| 인사이트(작가용 분석) | 조회·감상·유입 경로 | 분석 대시보드(KPI·일별·인기 사진·많이 본 작업) | ✅ (유입 경로는 없음) |

## 3. 시사점 — 무엇이 Happiness에 가장 값진가

Happiness의 북극성은 "사진가가 일을 받고 처리하는 것"이다(MASTER_PLAN v2). 그 기준으로 Behance 기능을 거르면:

- **가져올 것**: 의뢰인이 작가를 **찾는 경로**(작업 단위 탐색·지역 필터·고용 가능 배지)와, 작업 노트가 **반응을 받는 구조**(작업 감상·조회수 공개). 작업 노트(P0~P2)를 막 만들었는데 정작 그 작업이 포트폴리오 밖에서 발견될 길이 없다는 게 가장 큰 구멍이다.
- **가져오지 않을 것**: 라이브 방송·에셋 판매·채용 게시판·실결제 — 사진가 1인 업무 도구라는 방향과 멀고 비용이 크다. 추천 알고리즘도 지금 데이터 규모에서는 이르다.

## 4. 우선순위 제안

| 우선 | 항목 | 왜 | 대략 범위 |
|---|---|---|---|
| **P0** | **작업 탐색** — 탐색 화면에 "작업" 탭 추가, 공개 작업 노트를 촬영 유형·지역으로 필터 | 작업 노트를 포트폴리오 밖에서 처음으로 발견 가능하게 함. 의뢰인의 "이런 촬영 해본 작가" 찾기 | 백엔드 공개 목록 API 1개(페이징·필터), 웹 탐색 탭, 모바일 탐색 세그먼트 |
| **P0** | **"촬영 문의 받는 중" 배지** — 예약 가용 상태를 프로필·작업 카드에 노출 | 이미 있는 데이터(`BookingAvailability.active`)를 보여주기만 하면 됨, 비용 대비 효과 큼 | 포트폴리오·작업 응답에 플래그 1개, 배지 UI |
| P1 | 작업 감상(Appreciate) + 작업 조회수 공개 | 작업 단위 사회적 증거. 지금은 사진 좋아요만 있음 | `SeriesAppreciation` 테이블, 카운트 표시 |
| P1 | 이름 붙은 저장 보드(무드보드) | 의뢰인이 후보 작가 작업을 모아 비교하는 용도 | 저장 테이블에 보드 개념 추가(기존 저장 이전 필요) |
| P1 | 탐색 정렬에 조회순 추가 | PHOTO_VIEW 데이터가 이제 쌓이기 시작 | 조회 집계 쿼리 |
| P2 | 공동 작업자 크레딧 | 헤어·메이크업·모델 등 협업이 많은 촬영 특성 | 작업-회원 연결 테이블, 표시 |
| P2 | 작업 초안 | 공개 전 다듬기 | `Series.status` |
| P2 | 운영자 큐레이션(Featured) | 어드민이 우수 작업 선정, 탐색 상단 노출 | 어드민 화면 + 플래그 |
| 보류 | 라이브·에셋 판매·채용 게시판·실결제·개인화 추천 | 제품 방향과 거리, 비용 큼 | — |

## 5. 다음 단계

이 문서는 분석까지다. P0 두 항목(작업 탐색, 문의 받는 중 배지)을 구현하려면 별도 기획서
(`PLANNING_work-discovery.md`)와 디자인 프롬프트로 이어간다. 실제 Behance 화면으로 위 내용을 검증하려면 환경의 네트워크
허용 목록에 `behance.net`, `www.behance.net`, `mir-s3-cdn-cf.behance.net`을 추가한 뒤 REA로 다시 확인한다.
