## 1. 문제 — 지금 포트폴리오는 "고르기"만 되고 "짜기"가 안 된다

| 현재 | 결과 |
|---|---|
| 템플릿 4종(에디토리얼·미니멀·스크롤·다크룸) 중 **하나를 고르는 것**이 유일한 선택지 | 섹션 순서·노출 여부·문구를 작가가 못 바꾼다. 결혼식 작가와 제품 작가의 첫 화면이 똑같은 구조 |
| 추천사·언론·가격·클라이언트 섹션은 템플릿 코드에 **위치가 박혀** 있다 | "가격은 맨 위, 언론은 숨김" 같은 요구를 들어줄 방법이 없다 |
| `members.portfolio_sections_json`·`portfolio_style_json` 컬럼과 `PUT /portfolio/{p}/template`의 저장 경로는 **이미 있는데 어떤 화면도 읽지 않는다** | 확장 지점이 비어 있다. 게다가 저장 시 검증이 없어 아무 문자열(크기 무제한)이나 들어간다 |
| 새 섹션을 만들려면 템플릿 4개를 각각 고쳐야 한다 | 섹션 하나 추가 비용이 템플릿 수에 비례 |

## 2. Behance에서 가져올 것 (공개 기능 기준)

| Behance | 핵심 | 우리 앱으로 |
|---|---|---|
| 프로젝트 에디터의 **모듈**(이미지·텍스트·사진 그리드·임베드·오디오) | 페이지를 "모듈을 쌓아서" 만든다. 순서 드래그, 모듈마다 설정 | **블록**: 포트폴리오 페이지 = 블록 목록. 블록마다 종류·보이기·설정값 |
| 프로젝트 **스타일**(배경색, 모듈 간격, 글꼴) | 내용과 스타일 분리 — 스타일은 페이지 전체에 한 번 | **스타일 설정**: 강조색·배경·간격·제목 글꼴을 페이지 단위로 |
| 프로필 탭(작업·무드보드·감상·소개·서비스) + "Hire" | 보여주기와 일 받기를 한 페이지에 | 기존 작업 노트·추천사·가격·문의/예약을 **블록으로** 재사용 |
| Adobe Portfolio(테마 + 페이지 + 자유 배치) | 테마는 출발점, 이후 자유 편집 | 기존 템플릿 4종은 그대로 두고 **"직접 구성"(BLOCKS) 템플릿**을 하나 추가. 출발점 프리셋 제공 |

**가져오지 않는 것**: 픽셀 단위 자유 배치(캔버스 드래그) — 모바일에서 깨지기 쉽고 접근성 검사가 어렵다. "세로로 쌓는 블록 + 블록 안 설정"까지만 자유도를 준다(Behance 프로젝트도 세로 스택이다).

## 3. 설계 — 확장성과 자유도의 경계

### 3-1. 데이터 계약 (기존 컬럼 재사용, 스키마 변경 없음)

```json
// members.portfolio_sections_json
{ "version": 1,
  "blocks": [
    { "id": "b1", "type": "hero",   "visible": true, "props": { "tagline": "빛이 머무는 순간을 찍습니다", "align": "left" } },
    { "id": "b2", "type": "photos", "visible": true, "props": { "title": "최근 작업", "columns": 3, "limit": 12, "genre": "" } },
    { "id": "b3", "type": "text",   "visible": true, "props": { "title": "작업 방식", "body": "…" } }
  ] }
// members.portfolio_style_json
{ "version": 1, "accent": "#3182F6", "background": "light", "spacing": "normal", "headingFont": "sans" }
```

- **확장성**: 블록 종류는 서버 화이트리스트(`PortfolioLayoutValidator.BLOCK_PROPS`)와 웹 레지스트리(`blocks/blockRegistry.js`) **두 곳에 한 줄씩**만 추가하면 된다. 템플릿 코드는 손대지 않는다.
- **하위 호환**: `version` 필드로 나중에 구조가 바뀌어도 이전 데이터를 읽는다. 모르는 블록이 저장돼 있으면(예: 웹이 먼저 배포되고 서버는 이전 버전) 화면은 그 블록만 건너뛴다.
- **자유도**: 블록 순서·보이기·삭제·복제, 블록별 설정, 페이지 스타일. 같은 종류 블록 여러 개(텍스트 3개, 사진 그리드 2개를 장르별로) 허용.

### 3-2. 블록 카탈로그 (P0 12종)

| type | 이름 | 설정(props) | 데이터 |
|---|---|---|---|
| `hero` | 첫 화면 | tagline(80자), align(left/center), showStats | 회원 정보·커버 |
| `featuredWork` | 대표 작업 | title | 📌 고정 작업 |
| `works` | 작업 노트 목록 | title, showFilter | 시리즈 |
| `photos` | 사진 그리드 | title, columns(2~4), limit(3~60), genre(장르 코드 또는 빈 값) | 공개 사진 |
| `text` | 글 | title(60자), body(2000자) | — |
| `quote` | 인용 | text(300자), author(40자) | — |
| `testimonials` | 고객 후기 | title | 추천사 API |
| `pricing` | 촬영 패키지 | — | 가격 API |
| `press` | 언론·수상 | — | 언론 API |
| `clients` | 함께한 브랜드 | — | 브랜드 API |
| `contact` | 문의·예약 | title, body(300자), showBooking | 예약 받는 중 여부 |
| `newsletter` | 소식 받기 | — | 구독 API |

`spacer`/임베드(영상·외부 링크)는 P1 — 임베드는 URL 화이트리스트(유튜브·비메오) 검증이 따로 필요하다.

### 3-3. 서버 검증 (자유도와 안전의 경계)

- 원문 20KB 초과·JSON 아님·블록 31개 이상·모르는 블록 종류·잘못된 enum/hex → **400 + 사유** (조용히 버리면 작가는 저장됐다고 착각한다).
- 모르는 **설정 키**는 버리고, 문자열은 HTML 태그 제거 + 길이 컷, 숫자는 범위 클램프 — 다음 버전 웹이 보낸 새 설정 때문에 이전 서버가 400을 내지 않게.
- id는 `[a-z0-9-]{1,24}`가 아니면 서버가 새로 매긴다. 저장 응답에 정규화된 JSON을 돌려줘 화면이 서버 기준 값으로 맞춘다.
- 기존 템플릿을 고른 작가가 보낸 요청(`template`만)은 그대로 동작한다.

## 4. 사용자 흐름

1. 프로필 › 설정 › 포트폴리오 템플릿에서 **"직접 구성"** 카드 → "구성 편집하기" → `/portfolio-builder`.
2. 처음 열면 **출발점 3종**(작업 중심 · 일 받기 중심 · 사진 중심) 중 하나로 시작(기존 데이터가 있으면 그것을 연다).
3. 왼쪽 패널: 블록 목록(↑↓ 이동 · 👁 보이기 · ⧉ 복제 · ✕ 삭제) + "＋ 블록 추가"(카탈로그) + 선택한 블록 설정 + 페이지 스타일.
4. 오른쪽: **실제 공개 페이지와 같은 컴포넌트**로 그린 미리보기(내 사진·작업 데이터). 모바일 폭에서는 패널 아래로.
5. "저장하고 공개" → 템플릿 BLOCKS로 저장 → 내 포트폴리오 보기 링크. 저장 전 이탈 시 확인.

## 5. 수용 기준

- AC-1 템플릿 BLOCKS를 저장하면 `/portfolio/:p`가 저장한 순서·보이기·설정대로 블록을 그린다. 숨긴 블록은 안 보인다.
- AC-2 블록 추가·이동·복제·삭제·설정 변경이 미리보기에 즉시 반영되고, 저장 후 새로고침해도 같다.
- AC-3 잘못된 구성(모르는 종류·31개·20KB 초과·잘못된 색)은 400과 한국어 사유, 남의 포트폴리오 저장은 403(기존 유지).
- AC-4 HTML 태그는 저장 시 제거되고, 모르는 설정 키는 버려진다.
- AC-5 데이터가 없는 블록(추천사 0건 등)은 공개 페이지에서 빈 상자 없이 사라지고, 편집 미리보기에서만 "데이터 없음" 안내를 보인다.
- AC-6 기존 템플릿 4종 화면·동작 변화 없음. 390/768/1280px 가로 넘침 0.

## 6. 트레이드오프

| 선택 | 이유 | 대가 |
|---|---|---|
| 새 테이블 대신 기존 JSON 컬럼 | 스키마 변경·마이그레이션 0, 이미 저장 경로 존재 | 블록 단위 조회·통계가 어렵다(지금은 필요 없음) |
| 기존 템플릿을 블록으로 다시 만들지 않음 | 회귀 위험 0, 작가가 원할 때만 옮겨 탐 | 당분간 두 체계 공존 — P2에서 기존 템플릿을 "출발점 프리셋"으로 흡수 검토 |
| 세로 스택만(자유 배치 없음) | 반응형·접근성·모바일 안정 | 매거진식 비대칭 배치는 블록 안 설정으로만 |
| 드래그 대신 ↑↓ 버튼 | 키보드·터치에서 확실히 동작, 라이브러리 추가 없음 | 긴 목록에서 이동이 느리다 → P1 드래그(포인터 이벤트 직접 구현) |
| 모르는 설정 키는 버리고 모르는 블록은 400 | 앞으로 설정은 자유롭게 늘리고, 블록 종류는 서버가 아는 것만 저장 | 웹·서버 배포 순서: 새 블록은 서버 먼저 배포 |

## 7. 우선순위

- **P0(이번)**: 서버 검증·BLOCKS 템플릿, 블록 12종 렌더러, `/portfolio-builder`(추가·이동·보이기·복제·삭제·설정·스타일·출발점·미리보기·저장), 프로필 템플릿 카드, 통합 테스트.
- **P1**: 블록 드래그 정렬, `spacer`·`embed`(유튜브/비메오), 사진 블록의 "직접 고른 사진" 모드(사진 id 목록), 블록별 배경 덮어쓰기, 모바일 앱에서 구성 편집(지금은 웹 링크).
- **P2**: 기존 4개 템플릿을 블록 프리셋으로 흡수, 페이지 여러 개(소개·작업·가격 분리 — Adobe Portfolio의 페이지 개념), 커스텀 도메인, 블록 단위 조회 분석.
