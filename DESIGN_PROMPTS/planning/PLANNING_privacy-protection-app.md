# PLANNING — 개인정보 보호 강화 (App) — 어드민 조치와 동일 기준 (2026-10-21)

> 요청: "admin에서 처리했던 개인정보법 부분 확인하고서 동일하게 적용해줘"
> 기준: happiness-admin `docs/planning/PRIVACY_PROTECTION_PLAN.md`(커밋 34984ce, 브랜치 `claude/admin-planning-doc-120dha`) —
> 「개인정보 보호법」 제29조, 「개인정보의 안전성 확보조치 기준」 제5~8조. ⚠️ 조문은 어드민 기획서의 공개 해설 자료 기준이며,
> 최종 적용 전 국가법령정보센터 원문과 개인정보 보호책임자 검토가 필요하다.

## 1. 어드민 조치 ↔ App 점검 결과

| 어드민 항목 | App에서 같은 문제가 있나 (코드 확인) | 조치 |
|---|---|---|
| F1 공개 API가 회원 이메일·전화 반환 | **있음(치명)** — 비로그인 `GET /api/portfolio/{profileName}`이 작가의 `email`·`tel` 포함 `MemberResponse`를 그대로 반환. 로그인 회원이면 누구나 `GET /api/auth/member/{id}`(남의 id), `GET /api/auth/members/search`, `GET /api/follows/followers·following`으로 남의 이메일·전화 조회 가능 | 본인·관리자 외 응답에서 이메일·전화 제거(`MemberResponse.publicView`) — 화면은 이 값을 쓰지 않음(전수 grep) |
| F3 로그인 오류로 계정 존재 노출·실패 제한 없음 | 문구는 이미 단일("이메일 또는 비밀번호가 올바르지 않습니다") ✅. 그러나 **없는 계정은 BCrypt 비교를 건너뛰어 응답 시간 차이**, 실패 횟수 제한 없음 | 없는 계정·소셜 계정도 더미 해시와 BCrypt 비교, 같은 이메일 5회 실패 시 15분 잠금(429) |
| F4 관리자 화면 이메일·전화 원문 노출 | App 내장 관리자 목록(`GET /api/auth/members`, WM/SA)이 원문 | 목록 응답 마스킹(`us***@test.com`, `010-****-0002`). 원문 열람·접속기록은 **happiness-admin으로 일원화**(App 관리자 화면은 원문을 아예 못 보므로 열람 기록 대상이 생기지 않음) |
| F6 자유서술 필드 평문 | App 소유 컬럼(문의 본문·예약 메모 등)은 **공유 DB에서 어드민도 읽는다** | **이번엔 암호화하지 않음** — 어드민 기획서 3절과 같은 이유(한쪽만 암호화하면 다른 쪽 화면이 암호문을 표시). 공통 키·블라인드 인덱스 이관은 양쪽 공동 후속 과제 |
| F7 유휴 차단·토큰 수명 | 사용자 앱 access token 30분 + refresh 7일(어드민 8h보다 짧음) ✅. App 내장 관리자 화면에는 유휴 차단 없음 | `/admin/**` 화면 30분 무조작 시 자동 로그아웃 |
| 로그에 이메일 원문 | `AuditLogService`는 이미 마스킹 ✅ | 새로 남기는 로그도 마스킹 |
| 제7조 비밀번호 일방향 | BCrypt ✅ / 재설정 토큰은 SHA-256 해시만 저장 ✅ | — |

## 2. 수용 기준

- AC-1 비로그인 `GET /api/portfolio/{profileName}` 응답의 `member`에 `email`·`tel`이 없다(값 null).
- AC-2 남의 id로 `GET /api/auth/member/{id}` → 이메일·전화 없음. 본인·관리자는 원문.
- AC-3 `/members/search`·팔로워·팔로잉 응답에 이메일·전화 없음.
- AC-4 관리자 회원 목록의 이메일·전화가 마스킹되어 있다.
- AC-5 같은 이메일 5회 실패 후 6번째는 올바른 비밀번호여도 429. 성공하면 실패 횟수 초기화. 없는 이메일도 같은 문구.
- AC-6 관리자 화면 30분 무조작 시 로그아웃 후 로그인 화면.
- AC-7 내 정보 화면(프로필 설정)은 본인 이메일·전화를 그대로 본다(회귀 없음).

## 3. 트레이드오프

- 잠금은 인메모리(어드민과 같음) — 서버를 여러 대로 늘리면 Redis로 옮겨야 한다. 잠금은 이메일 기준이라, 남이 내 이메일로 일부러 틀려 15분 잠글 수 있다(어드민과 같은 선택 — IP 기준 전역 Rate Limit과 함께 동작).
- App 관리자 회원 목록의 이메일 검색은 마스킹된 값 기준이 된다(앞 2자·도메인). 원문 검색·열람은 happiness-admin에서.
