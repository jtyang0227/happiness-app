# 기획 — 작업 탐색 & "예약 받는 중" 배지 (2026-10-20)

> 근거: `ANALYSIS_behance-public-features.md` 4절 P0 두 항목. Behance의 "프로젝트 단위 탐색"과 "고용 가능 배지"를
> Happiness의 작업 노트·예약 가용 설정 위에 재해석한다. 디자인은 Toss 시스템 그대로.

## 1. 문제

- 작업 노트(시리즈 + 유형·클라이언트·시기·이야기)는 **작가 포트폴리오 안에서만** 보인다.
  `GET /api/series`는 `memberId` 없이 부르면 빈 목록을 돌려준다. 의뢰인이 "결혼식 촬영을 해본 작가"를 찾을 길이 없다.
- 작가가 예약을 받는지(`BookingAvailability.active`)는 데이터로 있지만 어디에도 표시되지 않는다.

## 2. 유저 스토리

- US-1 의뢰인으로서, 탐색 화면에서 **작업 단위로** 둘러보고 촬영 유형·지역으로 좁혀서, 내가 원하는 촬영을 해본 작가를 찾고 싶다.
- US-2 의뢰인으로서, 작업 카드와 작가 포트폴리오에서 **지금 예약을 받는 작가인지** 바로 알고 싶다.
- US-3 작가로서, 예약 가용 설정을 켜두면 내 작업과 포트폴리오에 자동으로 "예약 받는 중"이 붙었으면 한다(추가 설정 없음).

## 3. 범위와 규칙

### 3.1 작업 탐색 API — `GET /api/series/discover` (공개)
- 파라미터: `shootType`(작업 노트 어휘 7종 중 하나, 그 외 값은 무시 = 전체), `location`(작가 위치 부분 일치, 대소문자 무시, 50자 제한),
  `page`(기본 0), `size`(기본 24, 1~60 클램프).
- 포함 조건: 작가 포트폴리오가 **공개**(`Member.publicProfile = true`)이고, 사진이 **1장 이상** 있는 작업. (빈 작업은 탐색 가치가 없다.)
- 정렬: 최근 수정순(`updatedAt` desc, 같으면 id desc) — 작업 노트를 다듬은 작가가 앞으로 온다.
- 응답: `{ data: [...], page, size, hasNext }`. 항목 = 기존 작업 요약 필드(id·제목·커버·유형·클라이언트·시기·사진 수·미리보기 3장)
  + 작가 정보(`memberName`, `memberProfileName`, `memberAvatarUrl`, `memberLocation`) + `acceptingBookings`.
- 이야기(`story`) 전문은 목록에서 내려주지 않는다(카드에 안 쓰고 응답만 커짐).
- 성능: 작업 1페이지를 `Slice`로 가져온 뒤 작가·가용 설정·작업-사진·사진을 **각각 1회 배치 조회**(N+1 없음).

### 3.2 "예약 받는 중" 판정
- `BookingAvailability` 행이 **있고** `active = true`인 작가만 true.
- 행이 없는 작가는 예약 페이지가 기본값(평일 10:00·14:00)으로 열리긴 하지만, 작가가 직접 설정한 적이 없으므로 배지를 붙이지 않는다
  (기본값만으로 모든 작가에 배지가 붙으면 신호가 무의미해짐). 이 차이는 의도된 보수적 판정이다.
- 노출 위치: 탐색 작업 카드, 포트폴리오(`GET /api/portfolio/{profileName}` 응답 `acceptingBookings`) — 템플릿 4종 히어로/헤더, 작업 노트 페이지 상단.

### 3.3 화면
- 웹 `ExplorePage` 상단에 **사진 | 작업** 세그먼트(`?tab=works`로 공유 가능). 작업 탭: 촬영 유형 칩(전체 + 7종) + 지역 입력 + 작업 카드 그리드
  (3/2/1컬럼) + "작업 더 보기". 카드 클릭 → `/portfolio/:profileName/work/:id`.
- 모바일 `ExploreScreen` 상단에도 같은 세그먼트. 작업 카드 탭 → 웹 작업 노트 페이지를 시스템 브라우저로 연다(모바일에 작업 노트 화면이 없음).

### 3.4 범위 밖
작업 감상(좋아요)·조회수 공개·조회순 정렬·무드보드(P1), 공동 작업자 크레딧·초안·큐레이션(P2). 지역은 자유 입력 문자열 부분 일치만(행정구역 정규화 없음).

## 4. 수용 기준

- AC-1 비공개 포트폴리오 작가의 작업, 사진 0장 작업은 탐색 결과에 나오지 않는다.
- AC-2 `shootType=결혼식`이면 결혼식 작업만, `location=서울`이면 위치에 "서울"이 들어간 작가의 작업만 나온다. 둘 다 주면 AND.
- AC-3 가용 설정 행이 있고 active인 작가의 작업만 `acceptingBookings=true`. 설정을 끄면 false.
- AC-4 `page`/`size`/`hasNext`로 이어 불러오기가 된다. 잘못된 `shootType`은 400이 아니라 전체로 처리.
- AC-5 웹 탐색에서 탭 전환·필터·더 보기·빈 상태·스켈레톤이 동작하고, 카드에서 작업 노트 페이지로 이동한다.
- AC-6 포트폴리오와 작업 노트 페이지에 "예약 받는 중" 배지가 조건대로 보이고, 누르면 예약 페이지로 간다.
- AC-7 모바일 탐색에서 작업 탭이 같은 API로 동작한다.

## 5. 트레이드오프

- 정렬을 인기순이 아닌 최근 수정순으로 둔 이유: 작업 단위 반응(감상) 데이터가 아직 없다(P1). 지금 인기순을 흉내 내려면 사진 좋아요 합계를
  써야 하는데, 작업 질과 무관하게 사진 수가 많은 작업이 유리해진다.
- 배지 판정을 "가용일이 실제로 있는지"까지 계산하지 않는 이유: 작가마다 월 달력을 계산해야 해 목록 API 비용이 커진다. 설정 on/off는 작가의 의사 표시로 충분하다.

## 6. 구현 결과 (2026-10-20)

AC-1~7 모두 구현·검증. 백엔드 통합 테스트 2개(필터·빈 작업·비공개 제외·잘못된 유형·페이징 / 배지 on·off·미설정) 포함 24개 통과.
웹은 로그인 후 Playwright로 탭·유형·지역·빈 상태·카드 이동·배지(설정한 작가만, 링크 `/booking/:profileName`)·모바일 폭 가로 스크롤 없음을 확인.
모바일은 웹 번들 export까지만 확인(기기 미확인).

남은 것: `/explore`가 로그인 필수라 비로그인 의뢰인은 작업 탐색을 못 본다(공개 전환은 권한 정책 결정 필요). Editorial 히어로 버튼·통계 바 겹침은 기존 문제.
