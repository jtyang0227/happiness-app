# QA 기획 — 회원가입 입력 검증 (이벤트·모바일) (2026-10-21)

> 요청: "회원가입 정규식 체크가 이벤트 인/아웃이나 핸드폰에서 발생하는 부분이 누락된 것 같다 — QA 에이전트로 기획서 작성 후 개발"
> 점검: `reviewer` 에이전트(QA 역할) 정적 분석 + 코드 직접 대조. 대상: 웹 `pages/SignUpPage.jsx`, 모바일 `screens/SignUpScreen.js`,
> 백엔드 `MemberService.signUp`·`AuthController`(signup / check-email / check-profile-name).

## 1. 발견 사항

### 1.1 이벤트 경로 (사용자 지적 그대로)

| 필드 | 입력(change) | 벗어날 때(blur) | 붙여넣기·자동완성 | 제출 |
|---|---|---|---|---|
| 웹 이름·비밀번호·확인·전화 | 오류만 지움 | **검사 없음** | change와 같음 | 검사 |
| 웹 이메일·포트폴리오 주소 | 오류만 지움 | 중복 확인만(**형식 검사 없음**) | change와 같음 | 검사 + 중복 재확인 |
| 웹 인스타그램 | — | — | — | **검사 자체가 없음** → 서버 400 |
| 모바일 전 필드 | 값만 저장 | **검사 없음** | — | Alert 하나(첫 오류만) |

- 웹: 형식 오류를 **제출해야만** 알 수 있다. 고친 뒤에도 "비밀번호 확인" 오류는 비밀번호를 고쳐도 남는다.
- 웹: 중복 확인 응답이 늦게 오면 이미 바뀐 값에 대해 "사용 가능"이 뜬다(응답 경쟁).
- 모바일: 입력란별 오류 표시가 없고, 중복 확인을 하지 않으며, 서버 사유 대신 "Request failed with status code 400"이 Alert에 뜬다.

### 1.2 휴대폰에서만 생기는 문제

| 증상 | 원인 | 위치 |
|---|---|---|
| 이메일 끝 공백으로 형식 오류 | 키보드 자동완성·제안이 뒤에 공백을 붙임, 웹은 trim 없이 정규식 검사 | 웹 이메일 |
| 이메일·주소 첫 글자 대문자 | iOS 자동 대문자 — 웹 입력에 `autoCapitalize="none"` 없음 | 웹 이메일·포트폴리오 주소·인스타그램 |
| 하이픈이 다른 문자로 바뀜, 자동 수정 | iOS 스마트 구두점·자동 수정 — `autoCorrect`/`spellCheck` 끄지 않음 | 웹 전 텍스트, 모바일 이름·비밀번호·전화 |
| 비밀번호 자동 생성·저장 안 됨 | 모바일 `textContentType`/`autoComplete` 없음 | 모바일 비밀번호 |
| 전화번호 형식 제각각 저장 | 모바일은 포맷·검사 없음, 서버도 검사 없음 | 모바일·백엔드 |

한글 IME: 이름은 한글 조합 중 `change`가 여러 번 오지만 "비어 있지 않음" 검사뿐이라 영향 없음. 포트폴리오 주소·인스타그램은 한글을 입력하면 형식 오류가 즉시 뜨는데, 조합 중에도 같은 결과라 문제 없음(값을 강제로 바꾸는 웹 처리는 조합을 깨뜨리므로 웹은 **소문자 변환만** 하고 글자를 지우지 않는다).

### 1.3 규칙 불일치 (클라이언트 통과 → 서버 거절)

| 필드 | 웹 | 모바일 | 서버 |
|---|---|---|---|
| 포트폴리오 주소 | 3~30자(직전 수정) | 1~30자 | **1~30자**, 하이픈 시작·끝 불가 (오류 문구는 "3-30자"로 사실과 다름) |
| 인스타그램 | 없음 | `^[a-zA-Z0-9._]{1,30}$` | 같음 |
| 전화번호 | `01x-xxx(x)-xxxx` | 없음 | 없음 |

## 2. 결정

- **규칙의 기준은 서버.** 포트폴리오 주소는 서버 정규식(1~30자) 유지, 문구만 사실대로 고친다(기존 1~2자 회원이 프로필 저장 시 막히지 않도록 서버 규칙은 좁히지 않음).
- 전화번호: 서버에도 선택 검사 추가 — 비어 있으면 통과, 아니면 숫자만 뽑아 `01x` 10~11자리일 때 `010-1234-5678`로 정규화. 기존 행은 건드리지 않는다.
- 검사 시점(웹·모바일 공통): **벗어날 때(blur) 형식 검사** → 그 뒤 입력 중에는 **즉시 재검사**(한 번 건드린 필드만 — 처음 입력하는 동안 빨간 글씨가 먼저 뜨지 않게) → 제출 시 전체 검사. 비밀번호를 바꾸면 "비밀번호 확인"도 다시 검사.
- 정규화: 이메일 앞뒤 공백 제거(blur·제출), 포트폴리오 주소는 입력 즉시 소문자, 인스타그램 앞 `@` 제거.
- 중복 확인 응답은 **지금 값과 같을 때만** 화면에 반영.

## 3. 수용 기준

- AC-1 웹: 각 필드를 벗어나면 형식 오류가 그 자리에 뜨고, 고치는 즉시 사라진다. 제출 전에도 알 수 있다.
- AC-2 웹: `" a@b.com "`(앞뒤 공백)은 오류 없이 `a@b.com`으로 정리된다. `MyPortfolio`는 `myportfolio`로 입력된다.
- AC-3 웹: 인스타그램 `내-아이디`는 클라이언트에서 막힌다. 비밀번호를 고치면 "비밀번호 확인" 오류도 다시 계산된다.
- AC-4 웹: 오류 입력란에 `aria-invalid`, 오류 문구에 `role="alert"`와 `aria-describedby` 연결. 이메일·주소·인스타그램 입력은 자동 대문자·자동 수정 꺼짐.
- AC-5 모바일: 필드마다 벗어날 때 오류 문구가 입력란 아래 뜬다. 이메일·주소 중복을 벗어날 때 확인한다. 서버 실패 시 서버 사유가 보인다.
- AC-6 모바일: 비밀번호 `textContentType="newPassword"`, 이메일 `textContentType="emailAddress"`, 전화번호 자동 하이픈.
- AC-7 서버: 전화번호 `123`은 400 + 사유, `01012345678`은 `010-1234-5678`로 저장.
- AC-8 규칙 표(1.3)의 세 곳이 같다.
