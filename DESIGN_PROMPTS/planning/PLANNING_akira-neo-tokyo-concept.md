# 기획서 — AKIRA Neo-Tokyo 액센트 컨셉

작성일: 2026-08-18
담당: PM(기획) 역할

---

## 1. 배경

기존 "Cosmos × Pinterest 다크 에디토리얼" 방향(순수 블랙 배경 `#090909`, 이미지 온리 카드, 미니멀 네비)은
그대로 유지하되, **브랜드 액센트 컬러**가 인디고(`#5b6ef5`)/라벤더(`#a78bfa`)로 다소 무난하고 튀지 않는다는
피드백을 받았다. 애니메이션 **아키라(AKIRA, 1988)** 특유의 네오도쿄 사이버펑크 무드 — 어두운 도시,
그 위에 강렬하게 얹히는 레드 — 를 반영해 브랜드 액센트를 더 강렬하게 바꾼다.

단, "전부 빨간색"으로 칠하는 것은 명확히 요구사항에서 배제한다. 아키라 포스터/필름 자체도 화면 대부분은
어둡고 절제된 톤이며, 레드는 가네다의 오토바이·재킷 등 **소수의 포인트에만** 강렬하게 사용된다. 이 비율을
그대로 디자인 토큰에 적용한다.

## 2. 적용 범위 결정 (기획자 판단)

전체 화면을 새로 만드는 것이 아니라 **디자인 시스템 토큰 레벨**에서 적용한다.

- `COLORS.primary` 계열(버튼·링크·활성 탭·배지·CTA)만 인디고 → 아키라 레드로 교체
- `COLORS.accent` 계열(보조 하이라이트)은 라벤더 → 네온 시안(Neo-Tokyo 네온사인 연상)으로 교체 →
  레드 단독이 아니라 **레드+시안의 보색 대비**로 "아키라스러움"을 표현 (포스터의 붉은 바이크 + 푸른 네오사인 도시 구도와 동일한 논리)
- `bg`/`surface`/`text`/`border` 등 배경·본문 텍스트·테두리 토큰은 **변경하지 않는다** → 화면의 90% 이상을
  차지하는 배경/텍스트는 기존 블랙·화이트·그레이 그대로 유지되므로 "전부 빨간색"이 될 수 없는 구조.
- `danger`(삭제 등 위험 액션)는 기존 값을 유지해 primary(레드)와 시각적으로 구분되게 하고, 어드민 규칙상
  이미 이중 확인 다이얼로그가 붙어 있으므로 혼동 리스크는 없음.
- 웹(`frontend`)과 모바일(`mobile`) 양쪽의 컬러 토큰을 동일하게 갱신 → 플랫폼 간 일관성 확보.

## 3. 유저 스토리

- 사용자로서, 앱을 열었을 때 기존보다 더 강렬하고 개성 있는 브랜드 인상을 받고 싶다.
- 사용자로서, 버튼/링크/활성 상태가 화면 전체를 압도하지 않고 필요한 곳에서만 눈에 띄길 원한다.
- 디자이너로서, 향후 새 화면을 만들 때도 "레드는 CTA·활성 상태 전용, 배경은 블랙/화이트 유지"라는
  명확한 규칙을 참고하고 싶다.

## 4. 수용 기준 (AC)

- **AC1**: `frontend/src/constants/colors.js`의 `primary/primaryDark/primaryLight/primaryTonal`이
  아키라 레드 계열로, `accent`가 네온 시안으로 교체된다.
- **AC2**: `frontend/src/styles/theme.css`의 `:root` CSS 변수가 동일한 값으로 동기화된다.
- **AC3**: `mobile/constants/colors.js`도 동일한 브랜드 토큰으로 동기화된다.
- **AC4**: 소스 전체에서 하드코딩되어 있던 구(舊) 인디고/라벤더 hex 리터럴(`#5b6ef5`, `#4458e0`,
  `#eef0ff`, `#dde0ff`, `#a78bfa`)이 신규 팔레트로 일괄 치환된다 — 토큰을 참조하지 않고 직접 hex를
  박아둔 기존 컴포넌트들도 누락 없이 반영.
- **AC5**: `bg`/`surface`/`text`/`border`/`darkBg`/`galleryBg` 등 배경·텍스트·테두리 토큰은 변경하지 않는다
  (레드 사용 비율이 CTA/배지/활성 상태 등 기존 primary 사용처를 벗어나지 않도록 보장).
- **AC6**: `npm run build` 성공.
- **AC7**: 실제 브라우저에서 로그인/갤러리/탐색 화면을 확인했을 때 배경은 여전히 블랙/화이트가 지배적이고,
  레드는 버튼·활성 탭·배지 등 포인트에서만 보인다 (스크린샷으로 검증).
- **AC8**: `CLAUDE.md`의 "현재 디자인 방향" 섹션에 이번 액센트 변경 내용이 기록된다.

## 5. 트레이드오프

- **일괄 hex 치환 방식**을 택함 (컴포넌트 46개를 개별 리디자인하는 대신) — 리스크: 일부 컴포넌트에서
  치환된 색이 문맥상 어색할 수 있음. 완화책: 배경용 pale-tint(`primaryLight`/`primaryTonal`)와
  텍스트/아이콘용 saturated color(`primary`)를 구분해서 치환하여 명도 대비를 유지.
- **danger 컬러는 별도로 재조정하지 않음** — 향후 primary(레드)와 danger가 시각적으로 너무 가까워진다는
  피드백이 나오면 danger를 별도 톤(예: 딥 마젠타)으로 분리하는 후속 작업을 고려.
